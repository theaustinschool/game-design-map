## Conflicts noticed

- Images may be embedded in notes via Markdown, kept in a media sub-folder (help page, #how-can-i-include-images-in-my-notes) vs embedded images are not used in Zettelkasten notes (03-221).
- Saved search paired with an index note (release notes v0.4.2) vs saved searches don't create or manifest structure (05-526). Tension, not strict conflict.
- New tags: other:images (images embedded in notes), other:template (note header/template).
- Note body is "generally a short, atomic piece of information" (zh /introduction/zh/#单个笔记卡片的构成, Sascha Fast tr. Zhixiang Cai; wording absent from current English) vs. atomicity is not shortness and idea atoms come in different sizes (02-097, 02-124).
- Structure notes "do not contain any new content on their own" (Demo note 201705180836 Structure notes, Sascha Fast and Christian Tietze) vs. structure note opening with a bolded concept definition/summary and a visualization (02-127, 02-158; core image claim on slow-twitch-gap.webp) and writing text into structure notes (04-208).
- A structure note does "not simply list all the notes that are important for some purpose" (Demo note 201705180836) vs. link every new Zettel on a topic from that topic's Structure Note (02-051).
- Luhmann's register "is not important" for a digital archive because full-text and tag search give entry (Demo note 201705111034 Luhmanns Zettelkasten) vs. limit entry into the hypertext to a few central entry points, register-style (02-009).
- New tag: other:visualization (slow-twitch-gap.webp old-figure claim; Demo note 201705221802 on drawing/images).
- Direct clickable links beat ID-search links, which need three steps (Manfred Kuehn, https://zettelkasten.de/posts/you-dont-need-wiki/#comment-1934842945) vs a link via ID is already direct; clickable links saved no measurable time (Sascha Fast, https://zettelkasten.de/posts/you-dont-need-wiki/#comment-1937474432, #comment-2324174099; cf. 07-002)
- Keep a link to the source file/page so you can recheck context, because interpretations change (Dr Andus, https://zettelkasten.de/posts/nvalt-zettelkasten-implementation/#comment-1321486764; Eurobubba #comment-2346106292; Jaroslaw #comment-1321022016) vs notes must not link to text other than your own; needing to means you haven't extracted enough (Sascha Fast #comment-1320914975, #comment-1328402769) and source links tempt you to write less self-contained notes (Christian Tietze #comment-1329648473)
- Keep quote and triggered idea together in one note (Dr Andus, https://zettelkasten.de/posts/nvalt-zettelkasten-implementation/#comment-1331558065) vs separate interpretation from source reference, one thing per note (Christian Tietze, #comment-1329690078)
- Gather links in a separate "See also" section (Dr Andus, https://zettelkasten.de/posts/you-dont-need-wiki/#comment-1934468687; Erik Pischel, https://zettelkasten.de/posts/knowledge-cycle-efficiently-organize-writing-projects/#comment-2268020255) vs 07-2286 (Christian: no "See also" section, links there lack context) and 04-151 (Sascha: "see also" plus bare link is a bad habit)
- Functional categories (idea/memo/concept/list) in the header are useful (anttiherkko, https://zettelkasten.de/posts/no-categories/#comment-2029856721) vs they added noise and complicated search (Christian Tietze, #comment-2029876774) and Sascha calls them a distraction (#comment-2031781476)
- Outlines live outside the archive, are not part of it (Sascha Fast, https://zettelkasten.de/posts/no-categories/#comment-2032273184, #comment-2032281784; Christian Tietze #comment-2033801019) vs 03-653 / 03-661 (Christian: outlines live as files in the same archive) and 07-131 (Sascha: outline notes live in his archive). - Engagement notes are almost always worth putting into the archive, sometimes after redrafting (Sascha Fast, https://zettelkasten.de/posts/zettelkasten-building-blocks/#comment-2948429540) vs 04-100 (Sascha: engagement notes are not stored)
